Prompt: Why do I get the warning: Warning: Each child in a list should have a unique "key" prop.
Respuesta: If messages have internal state — for example if <Message> had its own useState (like an expanded/collapsed toggle), React could assign the old component's state to the wrong new message after a reorder.
For your chat specifically, since you only ever add to the end of the list and never reorder or delete individual messages, you'd likely never notice a visual bug. But it's still bad practice, and React warns you for exactly those edge cases where it would break.
{mensajes.map((msg) => (
    <Message key={msg.id} ... />
))}
Loops over every message in the array and renders a <Message> component for each one. key is required by React to efficiently track which items changed.

Prompt:  The nav bar, footer all start growing vertically as I send messages. They start small and as I send messages they start filling the screen.
Respuesta: the layout starts too small and grows as messages are added, meaning the body or main isn't actually filling the full viewport from the start.
Check your index.html — the root div likely has no height set:
<div id="root"></div>
React mounts into #root, but that div has no height, so your body { height: 100vh } chain breaks because #root itself collapses. Add this to your CSS:
#root {
  display: flex;
  flex-direction: column;
  height: 100vh;
}
